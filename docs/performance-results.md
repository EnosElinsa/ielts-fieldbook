# IELTS Fieldbook 性能验证结果

2026-10-13。实现位于 `codex/performance` 独立工作区，尚未执行线上数据库迁移、部署、推送或合并。主要代码改动已实现，性能验收尚未全部通过。

## 版本与测量条件

本地基线为 `3c5f67a6cb53abac03d97ba1193d68763a96a778` 的原始生产构建。线上基线为 https://ielts-fieldbook.pages.dev；其五个 JS 文件在测量当天与该本地构建 SHA256 一致。早期工作记录中的 `92cb7cf` 已纠正，未用于本报告比较。

优化版本使用最终工作区生产构建。`performance-results.json` 保存源文件快照哈希、测量脚本哈希、浏览器实际加载的 JS/CSS 哈希、固定数据哈希和逐次指标。所有比较使用相同题目和完整 55 词词组；两个视口分别运行每场景 15 次，使用最近秩法计算 p75。

- 下载 10 Mbps，延迟 150 ms；桌面 1440×900、正常 CPU；手机 390×844、4 倍 CPU 降速。
- 使用真实 Chrome 和合成账号；所有外部账号 API 均截获并模拟延迟与传输成本，没有读取或写入真实账号。
- 会话相对时间从 Supabase 读取注入的有效本地会话开始，不代表真实服务端身份验证耗时。
- 设置场景包含打开账号菜单及可编辑设置表单。词组和首次练习包含冷文档加载；练习终点是答题文本框出现，不等待题目图片。重复词组切页在同一会话内完成。
- 传输量来自 CDP 请求完成事件；切页窗口可能包含先前请求完成的字节。主线程指标为长任务时间，不是所有主线程 CPU 时间。

## 同版本本地比较

下表均为 p75。桌面/手机分别显示，单位毫秒。

| 场景 | 基线：桌面 / 手机 | 优化：桌面 / 手机 | 结果 |
| --- | ---: | ---: | --- |
| 冷启动登录页 | 1,572 / 1,921 | 601 / 809 | 减少 62% / 58%，通过 2.5 秒目标 |
| 打开设置表单，含文档启动 | 1,965 / 2,751 | 2,087 / 2,882 | 增加 6% / 5%，须继续优化 |
| 设置表单，会话相对时间 | 428 / 916 | 1,514 / 2,163 | 桌面低于 2 秒，手机未达标；真实验证后耗时尚待线上验证 |
| 普通保存确认 | 1,149 / 1,067 | 515 / 467 | 减少 55% / 56%，通过本地 1.5 秒目标 |
| 首次完整词组 | 8,560 / 9,126 | 2,441 / 2,658 | 均减少约 71%，通过减半目标 |
| 重复词组切页 | 65 / 260 | 55 / 164 | 通过 300 ms 目标，无重复业务数据请求 |
| 首次写作练习 | 2,422 / 2,669 | 1,930 / 2,084 | 减少 20% / 22%，未达到减半目标 |

登录首屏 JS 合计 **184,155 字节 gzip，约 180 KiB，3 个资源**，通过 300 KiB 预算。依赖检查和浏览器请求中没有登录页教学大 JSON、图表或音频模块。

请求量的代表样本：完整词组 230 → 75；首次写作练习 62 → 46；普通保存由 2 次业务写入、0 次写 RPC，变为 1 次业务写 RPC。保存的 2 个网络请求包含 CORS 预检。重复切页的单个请求是 favicon，不是词库或账号读取。

手机 p75 传输量：登录约 1,266 → 201 KiB；词组约 8,824 → 615 KiB；写作约 1,335 → 392 KiB。手机 p75 长任务时间分别约 234 → 59 ms、824 → 208 ms、483 → 55 ms。

线上旧版本冷登录基线为桌面 3,140 ms、手机 3,264 ms。此值单独记录，不能与本地优化数值混用为线上提升比例。没有优化版线上报告。

## 已验证的实现与正确性

登录与认证工作区分离；路由、弹窗、图表及音频按需要加载。词库构建生成哈希目录、完整词组包、词条分片及独立教学资源；正常浏览不请求完整 catalog。内容验证覆盖成员顺序、完整数量、义项和个人编辑；下载并发上限为 4，失败按相同范围回退。

题库读取采用 5 分钟会话内缓存、并发合并和后台刷新，失败保留旧数据并支持重试。切换账号清空并拒绝旧结果，签名音频地址提前 60 秒续签。阅读、听力、写作、口语相关缓存和状态行为均有测试覆盖。

账号基础加载只读取资料、计划和草稿。模块未加载与空数据明确区分；保存只比较已合并集合。写作和口语练习入口只等待 productive 与对应题库，提交时先确保词汇依赖。完整备份、合并与修复等待全部模块，保持 schema v11。

普通保存发送变化数据到 `commit_workspace_changes(batch)`。新增迁移验证原子回滚、同操作重试、冲突内容拒绝、账号隔离、RLS、白名单、不可变历史及服务端时间戳。800 ms 自动草稿合并、失败恢复、已确认基线和旧结果隔离均保留；专用词汇导入及测评事务继续使用。

最终检查：**103 个测试文件、847 项测试通过**；生产构建及首屏预算通过；两个独立 PostgreSQL/PGlite 事务检查通过；`git diff --check` 通过。独立代码审查未发现严重新增问题。截图检查覆盖桌面练习和手机完整词组。

## 仍需完成的验收与发布工作

1. 手机设置及首次练习性能仍不满足全部目标。设置弹窗首次下载和工作区依赖请求仍有成本；尝试提前预加载全部路由依赖、合并小分包未获得稳定收益，已撤回。后续应针对实际关键请求链进一步测量。
2. 本地 fixture 账号没有大量个人历史，不能证明真实大账号或服务端查询的绝对耗时。真实会话验证、数据库迁移、签名音频续签及主要真实操作需要 staging/线上验证。
3. 口语、阅读、听力已有功能测试，尚未各自完成 15 次浏览器性能对比。三个阶段的独立发布候选尚未组装；当前实现是集成工作区版本。
4. 匿名性能事件和有界指标在浏览器内记录，未接入中央错误率收集服务。不得宣称线上监控已经启用。

迁移和发布步骤、旧资源保留及回滚见 [performance-rollout.md](performance-rollout.md)。数据库迁移必须先于依赖它的前端发布。

## 重现

运行 rollout 文档中的基线、优化浏览器命令，再生成可归档汇总：

```sh
node scripts/summarize-performance.mjs --baseline=local/performance/baseline-authenticated.json --optimized=local/performance/optimized-release.json --online=local/performance/baseline-online.json --out=docs/performance-results.json
```

汇总脚本拒绝数据版本或网络条件不一致、缺少任意场景的 15 个样本、以及意外外部请求。详细原始报告和截图位于工作区的 gitignored `local/performance/`。
