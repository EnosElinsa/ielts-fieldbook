## Task 1: Foundation mastery and shared recommendations

Use meaning, listening and spelling as the foundation. Familiar requires 3 verified successes in each, Mastered 5, counted at least 24 hours apart. Preserve manual labels, legacy evidence and independent usage/production metrics. Active foundation mistakes block promotion; production-only mistakes do not. Keep FSRS scheduling after mastery. Update the next-practice and home recommendation rules to default to foundation practice (definition/dictation), with optional specialist practice still available. Studied means attempted, not necessarily correct; clarify this copy.

Produce `getVocabularyPlanningCandidates(store, now, preferredMode?)` in `src/domain/vocabulary/planning.ts`, returning prioritized `{card: ReviewCard, reason: 'error'|'recovery'|'due'|'missing'|'spaced' }[]`. Only saved learned senses are eligible; never-scheduled modes are missing-dimension opportunities, not overdue. Use confirmed eligible errors, scheduled due, missing dimensions, then spaced progress, with stable identity tie breaks and preference only within equivalent priorities. Respect each mode's actual FSRS date and 24-hour evidence window. Reuse the same foundation rules as home and next practice. Do not edit planTemplates, FieldbookContext, practice session controller or planning UI in this task. Test first, verify targeted suites and commit.

## Task 2: Planned vocabulary sessions and origin navigation

Add `planned-review` session selection `{kind:'planned-review', planId:string, cards:{entryId:string,senseId:string}[]}`. Validate exact distinct entry/sense pairs, allow multiple senses per word and legacy batches over 50, preserve frozen order and length despite free practice settings and dictation deduplication. Validate on draft restore and commit. Resolve planned cards from account plan target, loading requested resources first, never from free filters or untrusted query overrides. Preserve exact completion matching. Introduce vocabulary target `binding?:'dynamic'|'frozen'` (absent legacy with cards means frozen). At start, dynamically select current candidates for the target mode/capacity, excluding other active frozen targets, then save the frozen target before navigation. Empty due means skip with `skipReason:'no-longer-due'`, not complete; resource failure stays retryable. Keep existing learning batches.

Preserve Planning/Today provenance, query, task anchor and browser position through learning, setup, settings, results, refresh and recovery, allowing only vocabulary, planning and today internal paths. Direct URL fallback remains vocabulary. Task context rendering must distinguish resource failure, stale target and no-longer-due. Test first and commit.

## Task 3: Budgeted planner and backlog UI

Use Task 1 candidates, split definition/dictation homogeneous batches, cap one sense per word within each new batch, and reserve frozen entry/sense/mode identities. Count actual prompts at roughly one minute each; pending future review slots keep empty cards and dynamic binding instead of stale frozen references. Prefer due/recovery, then foundation gaps, then new learning in spare vocabulary budget. If reviews fill budget, pause new words. Preserve started work and manual future tasks. Consolidate pending past due-review plans with skipped status and `skipReason:'merged-review'`, preserving history. Carry over other pending/in-progress past tasks into the next 7 calendar days, started first then oldest, respecting daily and vocabulary budgets, rest days and indivisible task size. Unplaceable tasks remain collapsed backlog. Track `originalDateKey`, `rescheduledAt`, skip reasons; never change vocabulary FSRS/evidence while moving tasks. Make generation deterministic/idempotent; protect carryover material.

Add transactional bulk backlog preview and save through the existing plan queue: replan or skip selected tasks; pending selected by default, started only explicit opt-in, retain drafts/history and support retry. Show collapsed waiting list with counts, dates and actions rather than an unbounded overdue grid. Add schedule refresh at local midnight, foreground return, successful submissions, settings changes and explicit edits, without save loops. Expose pure preview/mutation helpers rather than sequential partial per-task writes. Tests cover budgets, rest days, stale duplicates, no capacity, manual and started work, skip/restore, failures and repeated refresh. Commit.
