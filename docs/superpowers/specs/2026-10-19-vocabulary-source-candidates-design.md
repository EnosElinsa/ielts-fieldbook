# Source-backed vocabulary candidate preparation

Extend the existing offline bulk workflow so an exported package can be joined to cached revision-bound Wiktionary responses. This removes repeated source lookup and source-to-sense matching from individual authoring sessions. The full dictionary objective, the existing ledger and all current teaching contexts remain intact.

The preparer consumes the current quality report, an exported work package and one or more MediaWiki query/revisions responses. It checks each work identity and both fingerprints against the current report. Source page titles remain case-sensitive. English definitions are matched by exact rendered original gloss and part of speech. Multiple matches, unsupported source templates, missing pages and changed teaching contexts require manual follow-up.

Only direct usage examples attached to that exact source definition may become suggested examples. Nested child examples, adjacent senses, translations, citations, truncated quotations, archaic text and relation lists cannot supply an automatic example. Preserve raw context and the revision URL so a reviewer can inspect rejected material. Existing collocations and distinctions may be copied into a draft, but missing fields stay missing; do not fabricate them from unrelated source text. Every output requires semantic review and zero items receive publication approval.

The CLI reads saved public data only, writes a separate ignored candidate artifact and never updates source dictionaries, teaching JSON or the review ledger. No new dependency, private account, model API or paid service is introduced. Integrate source-checked content separately through the existing attributed supplement and resource-baseline mechanism. Retain all prior resource bytes, personal edits, source-specific lessons, pronunciation bindings and frozen history.

Use the generated material to address the current truncated-example queue across words. Publish authored examples, collocations and context-specific distinctions for exact meanings; preserve specialised and ambiguous work in the complete queue. Diagrams remain selective and are added only when they convey information. Required release evidence remains tests, build, accounting, resource retention and local/production browser checks, followed by exact-commit CI and Cloudflare Git deployment.
